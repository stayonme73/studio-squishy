## Voice summary defect and correction

### Defect found by the first torture walk

`flyer_status` concatenated every available Machine field into one customer sentence. After intake, Board wake had already produced later facts, so Voice could stack individually true records into an impossible story, for example:

no upload yet + not assigned + work started + QA passed + email retrying + Review is open

Direct questions stayed coherent. The combined “what's happening?” answer was the honesty leak.

### Root cause

Voice treated the Machine drawer as the answer. Earlier resolved states and transport state were listed as if they were current blockers. Review-open plus leftover activation `pending_retry` plus a failed notice could all speak at once.

### Correction

Voice now determines the **current meaningful project state first**, then adds only supporting facts that still belong:

- Later authoritative production/Review/approval evidence suppresses obsolete blockers (`not assigned`, `no upload`, `getting the project ready`).
- Transport (queued / `delivery_failed` email) is never the project status. If Review is genuinely open, the primary sentence is Review-ready; email retry may follow as secondary.
- Unresolved `qa_fail` keeps Review closed. Campaign wake no longer silently re-binds a passing renderer over that fail and reopens Review on page load.
- Board and Voice still read the same Machine record.
